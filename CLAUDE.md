# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Babble is a Mastodon client for GNOME written in Python with PyGObject, on GTK 4.24+ and libadwaita 1.10+ (GNOME 51), with libsoup 3 for HTTP, libsecret for tokens, and libspelling 0.4+ (on a GtkSourceView 5 buffer) for spell checking in the composer. Meson is the build system. There is no Python packaging, linter config, or pytest suite.

## Commands

```sh
meson setup build                         # once
meson compile -C build                    # builds the gresource bundle, the launcher, and the schemas
meson test -C build                       # all tests
meson test -C build 'timeline memory'     # one test, by the name given in src/meson.build
meson test -C build -v 'compose widgets'  # -v shows the test's ok/FAIL lines
GSETTINGS_SCHEMA_DIR=$PWD/build/data python3 build/src/babble  # uninstalled run; not executable until installed, and only works with the build dir directly inside the source tree (it resolves ../../src). Without the schema dir it aborts: "Settings schema … is not installed"
```

Test names (besides the `validate …` and `po check <lang>` tests): `timeline render`, `timeline memory`, `thread profile render`, `thread cw`, `status fold`, `compose widgets`, `notifications render`, `oauth callback`, `oauth loopback`, `error summary`, `streaming helpers`, `account store`, `status text`, `search provider`, `catchup digest`, `catchup imports`, `catchup prewarm`, `catchup rank`, `catchup page`, `catchup grid`, `app lifecycle`, `schedule dialog`, `style css`, `ui strings`, `dialog toasts`, `dialog bases`, `breakpoints`, `a11y readback`, `dialog behaviour`, `translucent sidebar`, `wrapped styles`, `home filters`, `reading position`, `keyring errors`, `undo actions`, `module boundary`, `settings isolation`, `avatar cache`, `image decode`, `navigation`, `navigation window`, `stream dispatch`, `stream events`, `affinity`, `rank eval`, `bench compare`, `plugin boundary`, `api boundary`, `api registry`, `api golden`, `feature gates`, `instance limits`, `plugins`, `wallabag plugin`, `hashpanel plugin`, `bluesky text`, `bluesky card`, `media limits`, `media engine`, `media stream`, `media progressive`, `media quit`, `media settings`, `media inline`, `mediaviewer teardown`, `remote media`, `viewer entry points`.

Ten of those are rules rather than behaviour, and each exists because the rule was broken once or is invisible otherwise:

- **`ui strings`** reads every translatable string (via `ast`, so comments and docstrings are never read) and fails on a generic action label ("OK", "Yes", "No", "Done"), a British spelling, `e.g.`/`i.e.`, and `...` where `…` belongs. A value use of a generic word is excepted by the exact source snippet it appears in, so an exception cannot outlive its reason.
- **`style css`** loads `src/style.css` through a real `Gtk.CssProvider` and collects its `parsing-error` signal — which GTK 4.24 does emit, and which is the only way to see a malformed rule, since a bad declaration is otherwise just ignored. It also runs under `G_DEBUG=fatal-warnings`, as a second net for warnings GTK raises outside that signal.
- **`app lifecycle`** asserts the action set: that the app registers no `app.shortcuts` of its own (AdwApplication builds it from the `shortcuts-dialog.ui` resource), that F1 is `app.help` and not the shortcuts dialog, and that `app.preferences` reuses the open dialog.
- **`schedule dialog`** reads back the picker's spin rows' ranges and values, because `AdwSpinRow` is a row that owns a spin button rather than one: it has `get_value` and no `get_value_as_int`, and no `value-changed` signal (`notify::value` instead).
- **`module boundary`** reads every source with `ast`. New ranked-place modules may import only Catch Up rank modules (`rank`, `rank_model`, `rank_text`); Catch Up may not import window-owned `navigation`; `affinity.py` may not import the ranker; Catch Up tile rendering must construct action bars and menus through `tileactions`; rank modules may use only the standard library plus sibling rank modules; and `src/api/*.py` may use only the standard library and `core` (no `gi`, no gettext, no client or page code). `test-module-boundary.py` enforces these boundaries.

- **`settings isolation`** requires every `src/test-*.py` to select `GSETTINGS_BACKEND=memory` itself, before it imports `gi`. Meson sets it for you, but a script run by hand gets dconf, and a test that builds a `BabbleWindow` then restores the real stored account and forgets it when the keyring it sees has no entry. Account changes and the startup keyring read are logged at message level (`accounts: …`, with `BABBLE_PID`): `journalctl --user -g 'accounts:'`.

- **`api boundary`** reads every source with `ast` (no display needed) and compares the Mastodon call sites outside `src/mastodon.py` and `src/api/` with `src/api-boundary-allowlist.json`, which is EMPTY (phase 4): any site fails. The mechanism stays (the list may only shrink; an entry with no matching call fails). `BABBLE_BOUNDARY_PRUNE=1 python3 src/test-api-boundary.py` removes the stale entries for you (it prints each one, never adds, and normal mode never writes the file). Layers: `raw` names a path itself (`request_async`, `core.send_path`); `internal` is a generic helper's own send; `helper` hands a path or verb to a helper that sends it later. A helper handed a registered accessor (`send_relationship('follow')` with a verb of `api.relationships.ACTIONS`, or `api_accounts.list_path('followers', id)` on a name imported from `.api`) needs no entry; an unknown literal or a variable verb is still a site. `core.send_path(client, method, path, ...)` is the one sender of a path a caller supplies (`PagedList.refresh`/`load_more`, `ApiTimelineSource.fetch`, `TokenCompleter._search`); the test allows it only with a bare variable path and only in `completer.py`, `pages.py` and `timelinepage.py`, so a literal or a template, or a variable anywhere else, fails; a generic base class (`AccountListPage`) forwarding its own `path` parameter is not a site, since its callers name the path and are checked there. The test also fails on any `client.NAME_async`/`NAME_finish` call whose name `MastodonClient` no longer defines, so a leftover call to a moved wrapper is caught even where no scenario runs it. It also fails on any `request_finish`/`request_finish_paged` (called, taken as a value, or reached by `getattr`) outside `src/mastodon.py` and `src/api/`: UI code decodes with the api module's `<name>_finish`, or `core.finish`/`core.finish_paged` for a generic helper's caller-supplied path (no exceptions today).

- **`api registry`** imports `src/api/core.py`'s `registry` (no display needed) and holds every declared `Endpoint` to the same rules: a valid verb, a path starting with `/` whose placeholders are only `%s`/`%d`, a known-shaped OAuth scope (None only with a note), a docs URL on `docs.joinmastodon.org`, an int-or-None `min_version`, and a replacement named when `deprecated` is set. It imports every resource module (`statuses`, `accounts`, `relationships`, `lists`, `filters`, `announcements`, `scheduled`, `tags`, `search`) and asserts the registry holds at least 160 endpoints (so it cannot pass by checking nothing), and also requires a `#` anchor in every docs URL, no two endpoints sharing a method and path, and GET for every endpoint a path accessor serves to a paged view (`LISTS`, `PATH_ONLY`). A synthetic registry proves each rule can fail. It also fails when the generated "Endpoints" table of `Docs/mastodon-compat.md` (between the `api-table` markers) is out of date; regenerate it with `python3 src/test-api-registry.py --write-table`, never by hand.
- **`api golden`** records the wire request of each UI action at `MastodonClient._spawn` (no network) and compares it with `src/golden/api-requests.json`. `BABBLE_GOLDEN_UPDATE=1` rewrites that file, `BABBLE_GOLDEN_MUTATE=1` corrupts one path to prove the test can fail, and a diff after a refactor is a behaviour change, not noise. The plan is `Docs/api-layer-plan.md` and the endpoint audit is `Docs/mastodon-api-audit.md`.

- **`plugin boundary`** reads `src/plugin.py` and every `plugins/**.py` with `ast`: the contract imports only the standard library, a shipped plugin imports nothing of Babble's but `babble.plugin`, and it connects signals only through its extension or Context (`self.connect` in an extension class, `self.context.connect`, `context.connect`). A bare `widget.connect` reaching the extension is a cycle through C that keeps the page alive; `plugins` proves the scoped one does not.

- **First load is measured end to end, not with `load_ms`.** `load_ms` is CPU on a software renderer against a loopback server, so it cannot see what a reader waits for. Measure the real window under headless mutter (`mutter --headless --wayland --virtual-monitor 1280x1024 -- <cmd>`, on the GPU renderer) and log each stage: window constructed, `present()` returned, token read, request sent, response handled, first card painted. There is no committed benchmark for this; the trace is run by hand. Report every run, not a median: single runs spread 60-100 ms.
- Each test is a standalone script, `src/test-*.py`, that prints `ok - …` / `FAIL - …` lines. It exits 77 (a Meson skip) when there is no display (`DISPLAY` or `WAYLAND_DISPLAY`) or, for `timeline render` and `thread profile render`, no network: those two fetch live public data from mastodon.social. To run one headless, use the mutter line below with `meson test -C build '<name>'`, or fall back to `xvfb-run -a meson test -C build '<name>'`.
- Tests import modules as `src.<module>` through `BABBLE_SRCDIR`. Several need `GSETTINGS_SCHEMA_DIR=build/data`, so they need a compiled build tree. They also run with `G_DEBUG=fatal-criticals`, so any GTK critical fails the test.
- **The suite runs under headless mutter, not Xvfb.** CI and local verification both use it: a real Wayland compositor (GNOME 40+) with a frame clock and a GPU path, which Xvfb has neither of. The display guards accept `DISPLAY` or `WAYLAND_DISPLAY`, so nothing silently skips either way. The monitor size **must** be 1280x1024, or the geometry-sensitive tests (`compose widgets`, `timeline memory`) fail; xvfb-run's 640x480 default is why they used to flake:

  ```sh
  XDG_RUNTIME_DIR=$(mktemp -d) dbus-run-session -- \
    mutter --headless --wayland --no-x11 --virtual-monitor 1280x1024 -- \
    meson test -C build -j1
  ```

  Xvfb remains a fallback: `xvfb-run -a dbus-run-session -- meson test -C build -j1`. Under headless mutter the suite skips only `streaming helpers` (it needs a secret service); the last full run, after the media engine change, was 97 passed / 0 failed / 1 skipped, and the Xvfb count has not been re-taken. Two tests are the exception to "under mutter": `thread profile render` and `oauth callback` start their own Xvfb at 1280x1024 for a deterministic X11 screen (screenshots, a real window), so the `Xvfb` binary must be installed even when the suite runs under mutter; they crash rather than skip without it. This is also the honest way to measure first load, as the note above says: mutter headless is the only headless setup here with a real frame clock and a GPU path.
- **The suite pins `LANG=C`, `LC_ALL=C` and `GSK_RENDERER=cairo`**, in `test_env` and `fatal_test_env`. The locale pin is because a translated string is a different length and the widget tests assert geometry; CI already defaults to `C.UTF-8`, so without it a non-English desktop saw failures CI never could. The renderer pin is because letting GSK choose a GL renderer makes the suite need a GL context a container has no reason to have — when it picks one and cannot get a context, libepoxy aborts the process on `Couldn't find current GLX or EGL context`, which took `mediaviewer teardown` down with SIGABRT under Xvfb *and* under mutter alike. `GSK_DEBUG=fallback` does not save it. A test that needs a translation sets `LANGUAGE` itself and restarts.
- A new Python module also goes in `src/meson.build`'s install list, or the installed app won't have it — `file size rule` checks the root modules and the recursive `src/catchup/*.py` package against their install lists.
- **The stylesheet is loaded by AdwApplication, not by us.** `style.css` in the resource is loaded automatically, so do not add a provider for it: a second copy parses twice and the manual one does not take part in libadwaita's dark/contrast/reduced-motion reloads.
- **The help pages are not translated through `po/`.** A Mallard page is its own document; a translation is a translated page beside the English one under `data/help/<lang>/`, added to `help_languages` in `data/meson.build`. `po/babble.pot`'s header is rewritten by xgettext on every regeneration — the bugtracker address comes from `--msgid-bugs-address` in `po/meson.build` for that reason, and anything else typed into that header is lost.

Ranked timeline evaluation (`bench/rank_eval.py`, never installed): `collect` records one account's home timeline into `${XDG_CACHE_HOME:-~/.cache}/babble-eval/`, `evaluate` judges it day by day against `bench/rank_eval_gates.json` (the maintainer's file, H0), `aggregate` folds the per-account summaries into the Gate A record, and `self-test` checks the harness against a synthetic world with no network (`meson test -C build 'rank eval'`).

The three managed accounts (D2) live on `https://mastodon.social`: `babble_eval_a`
(`117482092944029604`), `babble_eval_b` (`117484163056225627`) and
`babble_eval_c` (`117484225356697601`). They were created by hand; the harness
only acts as them, and every server call goes through `src/mastodon.py`. The
account ids and the follow state are in `.eval-accounts.md` (git-ignored). The
recipe, in order:

1. Create one token per account (Preferences → Development → New application, or
   the instance's own token page) with the **`read write`** scopes: `read` is
   what `collect` needs, `write` is what `favourite`, `reblog`, `bookmark`,
   `reply` and `follow` need. `follow` is not a scope of its own since Mastodon
   3.5; `read`/`write` cover it, which is also what the app itself requests.
2. Put each token in the keyring, and note the account id it prints:
   ```sh
   python3 bench/rank_eval.py token --instance https://mastodon.social
   ```
   It reads the token from the terminal without echoing it (or from stdin when
   piped), verifies it with `verify_credentials`, and stores it under the id
   the server names. A refused token, or an `--account-id` that is not that id,
   stops it with a line and exit 2; the token is never printed on any path.
3. Check each account can see posts:
   ```sh
   python3 bench/rank_eval.py inspect --instance https://mastodon.social \
     --account-id 117482092944029604 --account-id 117484163056225627 \
     --account-id 117484225356697601
   ```
   `inspect` prints `following=`, `followers=`, `statuses=`, `home=` (first page
   of the home timeline) and `older=`. `home=0` means there is nothing to rank
   and the 14-day run cannot start. D2's shape is one account under 200 follows
   and one over 1,000; the accounts were seeded by import, and locked and
   remote accounts do not count until they accept, so `following=` can still
   rise.
4. To follow more (the API's limit is 400 follows a day):
   ```sh
   python3 bench/rank_eval.py follow --instance https://mastodon.social \
     --account-id 117484225356697601 --from-account YOUR_OWN_ID --limit 150 --pause 1
   ```
   `--from-account` is an account **on `mastodon.social`** to read the
   following list from — not the ursal.zone account the import used. The
   accounts already followed, and ones whose request is still pending, are
   skipped, so a rerun continues where the last one stopped. `follow` prints
   `followed=`, `requested=` (follows of locked accounts awaiting approval),
   `already=` and `refused=`. It sends `notify=false`, but the people
   followed are still followed by a bot-flagged account: keep the accounts
   quiet — no posts, and engagement only as the gates need it.
5. Start the collection, hourly, per account:
   ```sh
   python3 bench/rank_eval.py collect --instance https://mastodon.social \
     --account-id 117482092944029604
   ```
   **Each account's data is its own**, under the account id in the path, so
   `evaluate` needs the same `--account-id` to read it back:
   ```sh
   python3 bench/rank_eval.py evaluate --instance https://mastodon.social \
     --account-id 117482092944029604 --json /tmp/a.json
   ```
   `engage` produces the engagement T4.2 credits:
   ```sh
   python3 bench/rank_eval.py engage --instance https://mastodon.social \
     --account-id 117482092944029604 --kind favourite --target STATUS_ID
   ```
   A reply also needs `--text`, and a reblog or a reply a `--visibility`.
   The recorded posts never leave this machine; `evaluate --json` writes
   numbers, dates and verdicts only.

Memory leaks: follow `MEMORY-LEAKS.md`. `python3 bench/memwatch.py --trim` launches the uninstalled app (quit any running copy first; it is single-instance), samples RSS/CPU, and on Enter injects `bench/memprobe.py` through `sys.remote_exec` to report live objects, caches, textures and heap.

## Architecture

- **Launch.** `src/babble.in` is configured into `build/src/babble`. It registers the `babble.gresource` bundle (`window.ui`, `shortcuts-dialog.ui`, `style.css`, icons) and imports the package `babble`. Uninstalled, it binds the name `babble` to `src/` directly. `src/main.py` holds `BabbleApplication` (`Adw.Application`, `HANDLES_OPEN` for the OAuth callback URI, and all accelerators). `src/window.py` holds `BabbleWindow`, a `Gtk.Template` over `window.ui` that owns the login flow, session state, presentation and streaming lifecycle. `src/sidebarhost.py` owns sidebar rebuild, mode/visibility sync and pinned entries (above `sidebarmode` / `sidebarrail` / `sidebarcontrol`). `src/navigation.py` owns lazy place-page routing, titles, pinned-entry state, and the built local/federated pages (a view of its page cache). It reaches the window only through a `PlaceHost` of callables the window passes in, never through the window itself; the window owns widget presentation and stream lifecycle. `navigation window` checks that wiring on the real window.
- **API layer.** `src/api/` declares Mastodon endpoints once (`core.Endpoint`: verb, path template, OAuth scope, `min_version` (the gate a caller asks, None today), `mastodon_version` (the release string the docs name, e.g. `'4.5.0'`, or None; information only), docs URL, in `core.registry`) and `core.send()` sends them through the client's public `request_async`; `core.finish` decodes the body and `core.finish_paged` returns `(data, next_params, prev_params)` for a read a caller pages through. `statuses.py`, `accounts.py`, `relationships.py`, `lists.py` (lists, members, a list timeline, an account's lists), `filters.py` (v2 filters, JSON body), `announcements.py`, `scheduled.py`, `tags.py` (a tag, follow and unfollow, featured and followed tags, trending tags) `search.py` (`GET /api/v2/search`, one `search_async(client, q, **params)`), `timelines.py` (home, public, tag, link, favourites, bookmarks; `list_path(kind, *ids)` also serves the list timeline from `lists.TIMELINE`, and `LINK_PAGED` names the two kinds a Link header pages), `markers.py` (`GET`/`POST /markers`), `trends.py` (trending statuses and links; trending tags are `tags.trending_async`), `conversations.py` (the inbox, mark read, delete), `suggestions.py` (the v2 list, dismiss), `instance.py` (`GET /api/v2/instance` as `info_async`, which `MastodonClient.instance_info_async` sends through while keeping the caching and coalescing that `is_supported` reads; and `GET /custom_emojis`), `annual_reports.py` (the report, its state, generate: Wrapped) `notifications.py` (the list, unread count, clear, dismiss, the policy with its JSON `PATCH`, and the filtered-notification requests) and `admin.py` (the moderation dashboard: accounts v2 and the scope probe, review and action verbs, reports, measures and dimensions, and the four rule lists; JSON bodies for report updates, measures and dimensions; `ACTIONS`, `REPORT_ACTIONS` and `RULES` tables, `list_path(kind)` over `LISTS`), `collections_api.py` (Collections, Mastodon 4.6; named so nothing in the package can shadow the standard `collections`; create, get, update, delete, add, remove and revoke an item, and `list_path('by_account'|'featuring', id)` for the two tabs; JSON bodies), `polls.py` (get, vote), `reports.py` (`POST /reports`, form) and `media.py` (the v2 multipart upload and its status poll). `statuses.py` also holds `post_async`, `reply_async` and `edit_async` (JSON bodies, no `Idempotency-Key`), and `accounts.py` `update_credentials_async` (urlencoded, the posting defaults) with `update_credentials_multipart_async` (the profile editor) and `update_profile_async` (`PATCH /profile`). A multipart call goes through `core.send_multipart`, which calls the client's public `multipart_async` (transport, like `request_async`). The modules hold the verbs as `<name>_async(client, ...)`/`<name>_finish(client, result)` pairs. One naming: a function that picks an endpoint from a table by string is `<name>_async(client, id, operation, ...)` over a table called `ACTIONS` (`statuses.toggle_async` has two selectors, `(kind, active)`, over `TOGGLES`); a path accessor for a paged view is `list_path(kind, *ids)` over the module's `LISTS` (`search_path()` on `search` and `accounts`, and `familiar_followers_path()`, keep their shape; the completers' `search_request` hooks still return a path from one of them). UI code calls these and never spells a path of a moved resource (`api boundary` enforces it; `Docs/api-layer-plan.md` has the phases). `pages.call_api(widget, client, start, on_done, error_heading, finish=None)` and `PagedList.mutate_row_api(row, start, ..., finish=None)` are the helpers that take such a call; `finish=` is the api module's own `*_finish`, defaulting to `core.finish`; UI code never calls `client.request_finish` itself (`api boundary` enforces it). The path-taking `pages.call` and `PagedList.mutate_row` are gone; `fedicollections` sends through its `_send_api(client, start, on_ok, on_error)`. Every Mastodon endpoint Babble sends is declared in `src/api/` (the registry is rendered into `Docs/mastodon-compat.md`); `src/mastodon.py` keeps only the transport, the OAuth app, token and revoke calls (`auth=False`, not API endpoints of this layer), the keyring and the instance-info cache. Phase 5 (compliance fixes from `Docs/mastodon-api-audit.md`) is what remains.
- **API client.** `src/mastodon.py` `MastodonClient`: one per instance, fully async over a `Soup.Session`, and now the transport, authentication, OAuth and keyring layer. Operations that remain on it are `<name>_async`/`<name>_finish` pairs following the Gio.Task convention. The generic call is `request_async`/`request_finish` (`request_finish_paged` also returns the parsed `Link` header). It handles 429 rate limiting, OAuth with PKCE plus `state`, and keyring storage through the `*_secret_async` helpers. Accounts are stored in GSettings (`accounts`, `active-account`) through `src/accounts.py`.
- **Shared page toolkit.** `src/pages.py` is used by every secondary view. It provides the `settings()` singleton, navigation (`push_page`, `make_nav_page`, `window_of`, `client_of`), the dialog base `ToastDialog` (header, its own toast overlay, content slot), feedback (`show_toast`, `report_error`, `confirm`), `call()` for one-shot API calls, `PagedList` for Link-paginated boxed lists, `AccountRow`/`AccountListPage`, and `open_link` (routes post/profile/hashtag URLs inside the app). Reuse these instead of writing new plumbing.
- **Status text.** `src/statustext.py` holds `parse_content` (status HTML to safe text/link segments), `relative_time`, `shorten_url_text`, `is_hashtag`, `clock_format()` and `format_time()`. It builds no widget; it uses GLib/Gio only, so content parsing and absolute time formatting work without a display. Use `format_time()` for absolute dates/times instead of hardcoding `%H:%M`; it reads GNOME's 12/24-hour preference through the Settings portal.
- **Timeline core.** There is no `timeline.py`; import from the module that defines the name. It was split along five seams (ARCH-06), and `test-file-size.py` keeps each under the 800-line limit:
  - Data, `src/timelinedata.py`: `StatusItem` (GObject wrapping a status dict, emits `changed` on in-place edits) and `TimelineModel` (`Gio.ListModel`). `src/statusrun.py` holds `RunModel`, which groups consecutive same-thread posts by one author into a `StatusRun` and emits minimal splices, and `StatusRunRow`, the list shell. Shared constants, `status_filter` and time helpers are in `src/timelinebase.py`.
  - View: `src/timelinepage.py` holds `TimelinePage` (a `Gtk.ListView` with `TimelineFactory`) and `ApiTimelineSource`, which adapts any Status-array endpoint with `paging='id'|'link'|'none'`. Each list item is a `StatusRunRow` containing one or more `StatusRow` cards (`src/statusrow.py`; its content warning and Show More/Less folds are the `StatusFold` mixin in `src/statusfold.py`). The action bar and overflow menu are `StatusActions` (`src/statusactions.py`) and `StatusMenuButton` (`src/statusmenu.py`), shared with Catch-Up's tiles.
  - **Tile actions:** `src/tileactions.py` provides the shared `tile_action_bar(item, client)` and `tile_menu_button(item, client)` adapter used by timeline rows and Catch Up tiles; controls share `StatusActions` and `StatusMenuButton` without duplicate construction wiring.
- **Bluesky.** Posts bridged from Bluesky (Bridgy Fed) and bsky.app links read natively, behind the `bluesky-native` setting. `src/bskytext.py` is pure (standard library only): URL forms, `bridged_ref(status)`, `card_post(card)` (a Mastodon preview card to the quoted post) and the AppView post helpers. `src/blueskycard.py` draws the timeline `BlueskyQuoteCard` and the "Bluesky" indicator from the Mastodon card alone, with **no network and a fixed height**, and `fill_card_box` keeps the child when the card is unchanged. `src/bluesky.py` is the public AppView (module functions, never a `client`), reached only from `src/blueskythread.py`, the read-only thread page, after a click; a handle is resolved to a DID first because the AppView answers HTTP 500 to a handle inside an `at://` URI. `parse_content(html, drop_quote_inline=True)` hides the "RE: <link>" line when the quote is shown as a card. `statusrow.py` stays near its line limit, so row logic lives in these modules.
- **Plugins.** `src/plugin.py` is the public, versioned API (`X-Babble-Api=1`, a preview); `src/pluginhost.py` is the host. libpeas 2 finds `.plugin` files (in `BABBLE_PLUGIN_PATH`, `~/.local/share/babble/plugins`, then `plugins/` beside the package) and imports the module; the host finds the `PostMenuExtension`/`HashtagPageExtension`/`PreferencesExtension` subclasses itself, because libpeas only instantiates GInterface or abstract types and PyGObject can define neither. The enabled list is `active-plugins`; while it is empty libpeas is never imported. A post menu extension lives as long as its plugin, a hashtag page extension as long as its page, a preferences extension as long as its settings subpage (both released from the page's GObject weak ref); `Context.data` is the state a plugin's extensions share. The Plugins page (`src/pluginspage.py`, `app.plugins` in the main menu) is its own single-page Adw.PreferencesDialog, not a Preferences tab, and opening it is what starts the host. Anything a plugin raises is caught by `_Context.guard`, which turns the plugin off. `Context.connect` holds a callback that is a GObject's method weakly, so a plugin's dialog connecting its own buttons is freed when it closes. The shipped plugins live in `plugins/<name>/`, named `babble_<name>` so their module cannot collide with an installed package; their strings go through `plugin.gettext` (Babble's catalogue), are listed in `po/POTFILES.in` and are checked by `ui strings`. Python cannot unload a module, and libpeas keeps a failed import until restart.
- **Streaming.** `src/streaming.py` `StreamingManager` multiplexes Mastodon streaming subscriptions (user, public, list, hashtag) and feeds inserts, edits, and deletes into open pages.
- **i18n.** Always import `from .i18n import gettext as _` (and `ngettext`), never the stdlib `gettext` directly. The cached catalogue is a measured hot-path optimization. Use `ngettext` for any count, and add a `# Translators:` comment right above the `_()` line for terse or format strings.
- **Translations.** `po/LINGUAS` lists de, es, fr and pt_BR. After changing strings, run `meson compile -C build babble-pot` and then `babble-update-po`. The `po check <lang>` tests run `msgfmt --check-format`; `msgfmt` and the other validators are `required: false` in meson so a missing one warns instead of breaking the build — `.github/workflows/ci.yml` installs them and fails the run on a skipped test, which is where the guarantee lives. The `interface-language` key (Preferences → Language) is applied in `src/babble.in` by setting `LANGUAGE` before anything translates, which is why it only takes effect on restart. A new language also goes into `INTERFACE_LANGUAGES` in `src/preferences.py`.

## Conventions that matter

- **Memory and leak discipline (important).** When a widget connects a signal on something it owns to one of its own methods, use `pages.connect_weak(emitter, signal, self.method)` or `pages.weak_method(...)`, not `emitter.connect(signal, self.method)`. A plain connect forms a C-level cycle that Python's GC cannot see, and the row, page, or dialog leaks. These helpers use GObject weak refs, not Python `weakref`, because PyGObject 3.58 re-creates wrappers of GTK-held widgets. `src/test-timeline-memory.py` checks that pages and rows are actually freed. Run it after touching timeline, notifications, profile, or paged views.
- **Tearing a video down.** Playback is one `mediaengine.Engine` (a GstPlay and its `gtk4paintablesink`) per viewer, wrapped for each attachment in a `mediastream.EngineStream` (a Python `Gtk.MediaStream`, so `Gtk.Video`, `Gtk.MediaControls` and the GIFV `Gtk.Picture` are unchanged). Freeing a GstPlay can crash (SIGSEGV in `g_type_check_instance_is_fundamentally_a` under `gst_message_new_custom`, libgstplay). Measured, not explained: freeing it right after `pause()` then `stop()` under a `Gtk.MediaStream` in a `Gtk.Video` crashed 6 of 7 twelve-cycle runs, while a plain `stop()` then free survived 500 cycles; the real viewer on `main` crashed 4 times in about 415 open/close cycles. The precise trigger is not identified, and waiting for `STOPPED` removed it in every variant tested, so never drop an engine directly: `Engine.release()` stops it, waits for the adapter's `STOPPED`, disconnects every handler, and drops `play`, `adapter`, `sink` and `paintable` from `GLib.idle_add` (a 1 s timeout does the same if `STOPPED` never comes); until then the engine sits in `mediaengine._releasing`. Navigating inside a viewer reuses the engine (`stop()` then `load()`); `close()` releases it. At quit `BabbleApplication.do_shutdown` calls `mediaengine.shutdown_all()`, which stops every engine and turns the main context until `STOPPED` (bounded), because interpreter teardown freeing a playing GstPlay crashed 17 quits in 50. An engine's handlers are connected once and tracked; events reach the owner by `owner._engine_event(...)`, never by a closure that captures it (that leaked the stream). The stream must `stream_prepared` from the preroll (`load()` is `set_uri` + `pause`), with `seekable` from the media info, and never forwards a seek when not seekable. **The viewer streams**: `_start_stream(attachment, url)` loads the remote URL straight into the engine (souphttpsrc, Range requests, no download or temp copy); `Engine(user_agent=...)` sets Babble's User-Agent on the source in `source-setup` (a GStreamer thread: properties only). The stream is prepared once, on the first known duration or `DURATION_WAIT_MS` after the media info, never re-prepared, and exposes `buffering` (the viewer shows a spinner after 1 s). A server that ignores Range and sends no `Accept-Ranges` fails the preroll for demuxers that read the tail (Ogg); it plays a faststart MP4, only unseekable (measured), and `Accept-Ranges: none` plays unseekable. There is deliberately no download fallback: the user gets the error page with Retry and Open in Browser. Metered gates only the start. Tests: `media engine`, `media stream`, `media progressive`, `media quit`, and `mediaviewer teardown` (the real `present_media()` path, 50 cycles). **Inline GIFVs** (`src/mediainline.py`): one `InlinePlayer` per window (an attribute of the window, which it holds only by GObject weak reference) owns at most one engine and plays the one GIFV tile that is at least 50% inside its scrolled window and has the largest visible share. `MediaBox` builds a `GifvTile` for a GIFV; it registers on map and unregisters on unmap, so recycled rows cost nothing. Switching tiles is `stop()` then `load()`, a tile keeps its poster until the first frame, and the engine is released (deferred) after `RELEASE_DELAY_MS` without a candidate, at once when the window is hidden or closed, and while the viewer is open. Live gates: `may_autoplay_loop`, `media-autoload` with the metered state, and `remote-media` (a copy on another server plays only under `load`, and nothing is ever asked from the timeline). It ships OFF by default behind `inline-animated-media` (Preferences, Reading, Media), because it still fails the bench gate (PERFORMANCE.md): the first play imports GStreamer on the main thread (about 45 ms in one dispatch) and what that loads stays resident (+12 MB). Its engine is made with `gl=False`, which decodes into an `appsink` and shows each frame as a `Gdk.MemoryTexture` (`mediaengine.FrameHolder` stands in for the sink's paintable); `gtk4paintablesink` creates a GL context on the main thread whatever the caps, on the first state change if not before (about 70 ms and +78 MB retained, measured), so never use it for an inline tile, and the new-sample callback runs on a GStreamer thread: it copies the frame and hands it over with `GLib.idle_add`, touching nothing else. The viewer (`gl=True`) keeps the sink and `glsinkbin`. That key must be on as well as the gates above, and with it off the player is inert: no engine, no after-paint handler, no per-scroll handler (the adjustments are watched only while it is on, live on `changed::inline-animated-media`). At most one engine per window. A playing tile gets a lazily built Pause Animation button (and a Play Animation one when the reader paused it), kept in the row's `ui` by attachment id, shown only while the key is on; a paused tile is not resumed on its own, and clicking the tile still opens the viewer. The media viewer opening makes the player give way (`present_media` calls `mediainline.viewer_opened` once the viewer exists, `close()` calls `viewer_closed`). It re-evaluates after the frame that lays the tiles out, not from an idle (positions read before the layout are the ones from before the scroll). `mediaengine` schedules a `malloc_trim` when an engine stops and when it is dropped: each load and stop on one engine otherwise left about 16 MB resident. An Ogg stream cannot loop over HTTP in GStreamer 1.28.8 (the seek back to the start after the end fails; MP4 and WebM loop), so the fixtures use a clip longer than any check. Test: `media inline`.
- Read-only `InlineEmojiText` bodies are pinned to `gtk-im-context-simple` on purpose (an IBus context leaked them). Don't make them editable without revisiting that.
- `StatusRow` builds optional parts (boost strip, CW bar, carousel, overflow menu, …) lazily. Keep new row features lazy, and prefer mutating the existing `StatusItem` and emitting `changed` over replacing items in the model.
- In `src/style.css`, use libadwaita palette variables (`var(--card-bg-color)`, `var(--border-color)`, …), not deprecated `shade()`/`alpha()`/`@named_colors`.
- Files carry `# SPDX-License-Identifier: GPL-3.0-or-later`. Imports after `gi.require_version` are marked `# noqa: E402`.
- App ID and resource base path: `io.github.mauriciobc.Babble` and `/io/github/mauriciobc/Babble`. GSettings keys live in `data/io.github.mauriciobc.Babble.gschema.xml`. Add the key there before reading it.
- **An account is `(id, instance)`, never the id alone.** Mastodon ids are server-local, so two instances both hand out `42`. `accounts.account_key()` builds the `'<instance>#<id>'` name a stored account is switched and removed under; `active-account` holds that key. A bare id left over from before the pairing still resolves when it is unambiguous.
- **Style is `ruff check src/`**, configured in `ruff.toml`. It encodes what the code already does: `%` formatting is kept on purpose, and `E402` is off because every module calls `gi.require_version()` between its imports.
- **File size.** The modules the window was broken into — `portals.py`, `auth.py`, `drafts.py`, `clipboard.py`, `navigation.py`, and `sidebarhost.py` — stay under 800 lines. The `file size rule` enforces that limit and recursively checks every `src/catchup/*.py` module. **`window.py` remains a declared exception:** it owns session state, presentation, and streaming lifecycle over window-owned page containers; moving those responsibilities would invert their dependency rather than cut a seam. Reach for a new module when a cluster has a boundary, not to move a line count.
- **Capability gating.** Ask the client, never the dict: `client.mastodon_api_version()` returns the instance's `api_versions.mastodon`, or `None` when the server says nothing — 0 and None are not the same answer, and only one of them means "Mastodon that old". `client.is_supported(min_version, when_unknown=False)` collapses the tri-state with the caller's policy, so a call site does not spell out `is True`. Every gate constant lives in `src/capabilities.py` (`COLLECTIONS_API_VERSION = 10`, `PROFILE_TABS_API_VERSION = 8`, `PROFILE_ALT_TEXT_API_VERSION = 9`, `ENDORSE_API_VERSION = 6`, `LINK_TIMELINE_API_VERSION = 2`, `ANNUAL_REPORT_STATE_API_VERSION = 8`, `NOTIFICATION_POLICY_API_VERSION = 2`, `FILTER_BLUR_API_VERSION = 5`, `QUOTES_API_VERSION = 7`, `ENDORSEMENTS_API_VERSION = 6`). A gate on a feature the UI shows takes `when_unknown=False`; one on a request whose failure is invisible or explained takes `when_unknown=True` (the notification gates, since the page can be built before the instance document arrives). `Endpoint.min_version` holds the same number for the calls a caller gates (`src/api` may not import `capabilities`, so `api registry` holds the two equal); `feature gates` is the test that tries each gate below, at, above and unknown. `Docs/mastodon-compat.md` is the list; the `capability gates` test is the reason the parse cannot drift back to three different spellings, and `version gate call sites` is the reason a caller cannot compare the accessor directly instead of asking it.
- **OAuth.** The login asks for `read write` and nothing else — every requested scope is listed on the instance's consent screen, so the admin scopes belong only in the extra authorization `window.authorize_admin()` runs. (`follow` was dropped when Mastodon 3.5 deprecated it; `read`/`write` cover every granular follow, block and mute scope.) Scope strings must agree between `register_app_async(scopes=…)` and `get_authorize_url(scopes=…)`; Mastodon refuses the authorization otherwise, and one unrecognised scope fails the whole registration with a 422.
